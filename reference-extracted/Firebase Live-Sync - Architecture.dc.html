3 · SETUP (ONE-TIME, ~10 MIN)
1. console.firebase.google.com → Add project (e.g. eprom-reports) — no Analytics needed
2. Build → Firestore Database → Create (production mode, region eur3)
2b. Build → Authentication → Sign-in method → enable Email link (passwordless), and under Settings → Authorized domains add the domain the reports run on. Signed-out users see a slim bar at the bottom of the report: enter work email → click the emailed link → signed in, no passwords
3. Project settings → Your apps → Web app → copy the firebaseConfig object
4. Paste it into firebase-sync/firebase-sync.js (the var CONFIG line) — the adapter is inert until then
5. Firestore → Rules → paste the rules below → Publish
6. Whitelists (two levels): each person opens a report, signs in via the email link, and sends you the UID from the browser console (also under epromFbUid in DevTools → Local Storage). In Firestore create two collections and add docs whose ID = the UID (fields optional, e.g. name):
· editors — required for any write; everyone not listed is read-only
· admins — additionally may Approve/lock and edit locked reports (admins also need an editors entry)
rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { // admin = a doc exists at /admins/<your UID> (content irrelevant) function isAdmin() { return request.auth != null && exists(/databases/$(database)/documents/admins/$(request.auth.uid)); } // editor = a doc exists at /editors/<UID> — required for ANY write function isEditor() { return request.auth != null && exists(/databases/$(database)/documents/editors/$(request.auth.uid)); } match /admins/{uid} { allow read: if request.auth != null; allow write: if false; // manage ONLY from the Firebase console } match /editors/{uid} { allow read: if request.auth != null; allow write: if false; // manage ONLY from the Firebase console } match /eprom-reports/{doc} { allow read: if request.auth != null; allow create, update: if isEditor() && request.resource.data.keys().hasAll(['v', 'updatedAt']) && request.resource.data.v is string && request.resource.data.v.size() < 200000 // ≤ 200 KB per report && request.resource.data.updatedAt is number // stale writes lose — last-write-wins server-side: && (resource == null || request.resource.data.updatedAt >= resource.data.updatedAt) // editing an already-LOCKED (approved) report → admins only: && (resource == null || resource.data.locked != true || isAdmin()) // setting the lock (Approve & Upload) → admins only: && (request.resource.data.locked != true || isAdmin()); allow delete: if false; // reports are never deleted from the app } } }
Auth-hardened: unauthenticated traffic is rejected, payloads are schema- and size-checked, stale writes lose server-side, deletes are blocked. The admin PIN stays app-level and the 🔒 uploaded lock still blocks edits in the UI. Sign-in is passwordless email-link, so every UID maps to a real team mailbox. All writes require an editors entry (everyone else is read-only); locking/editing locked reports additionally requires admins (step 6).
4 · BEHAVIOUR GUARANTEES
✓ Offline-first — no internet: everything keeps saving locally; Firestore queues and reconciles on reconnect
✓ Instant cross-form — weekly edits recompile any open Monthly in ≤ 1 s (same tab-sync path as today)
✓ Lock propagation — Approve & Upload sets stage=2 in the doc; every device sees 🔒 read-only immediately
✓ Role badge — corner chip after sign-in: 🔒 Read-only (amber) when the UID isn't in editors — hovering shows the UID to send the admin; ★ Admin (green) for whitelisted admins; editors see no chip
△ Conflicts — two people editing the same week: last write wins per report (400 ms debounce); field-level merge is a later upgrade
